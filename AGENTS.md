# Инструкции для AI-агентов

## Назначение

Ecstasy — будущий Telegram Bot + Telegram Mini App с AI-ответами через разрешённое Telegram Business-подключение. Репозиторий сейчас содержит требования и документацию; приложение ещё не реализовано.

## Состояние проекта

- Ветка разработки: `main`; основной remote: `origin`.
- Текущий этап: Этап 0 завершён; следующий — Этап 1, после проверки документации и необходимых доступов.
- Не заявляй о готовых приложении, API, инфраструктуре или деплое.
- Не переходи к следующему этапу без завершения проверок и фиксации результата текущего.
- Перед началом работы прочитай `telegram_ai_mini_app_prompt.md.txt` и связанные документы ниже.

## Текущая структура

- `telegram_ai_mini_app_prompt.md.txt` — исходные продуктовые требования и ограничения.
- `AGENTS.md` — эти инструкции.
- `ARCHITECTURE.md` — согласованная целевая архитектура.
- `DESIGN_SYSTEM.md` — визуальное направление и токены.
- `ROADMAP.md`, `TASKS.md` — этапы и текущие задачи.
- `ENVIRONMENT.md`, `DEPLOYMENT.md`, `SECURITY.md`, `API.md` — конфигурация и проектные требования.
- `CHANGELOG.md` — значимые изменения документации и проекта.
- `docs/superpowers/specs/` и `docs/superpowers/plans/` — согласованные дизайн и план Этапа 0.

Исходников, `package.json`, lock-файла, тестов и конфигурации Cloudflare пока нет. Поэтому команды установки, разработки, тестирования и сборки ещё не определены; не выдумывай успешные результаты.

## Целевая архитектура

TypeScript, React и Vite для Mini App; один Cloudflare Worker со статическими файлами, API и Telegram webhook; Hono для маршрутизации; D1 для реляционных данных. Подробности и нерешённые вопросы — в `ARCHITECTURE.md`.

## Правила

- Соблюдай продуктовые ограничения в мастер-промпте; не придумывай данные, функции, аккаунты, домены или состояния подключения.
- Используй Telegram Business только в рамках API и явно выданных разрешений. Не обещай доступ к полной старой истории.
- Проверяй `initData`, права и владение ресурсами на сервере; требования безопасности описаны в `SECURITY.md`.
- Никогда не добавляй токены, ключи, пользовательские данные и локальные секреты в Git, логи, frontend или документацию.
- Реальные значения секретов, присланные в чат или логи, считай раскрытыми. Не используй и не копируй их; сообщи владельцу о необходимости отзыва и ротации.
- Храни локальные секреты только в игнорируемом локальном файле. Для production используй Cloudflare secrets/bindings после отдельной проверки настройки.
- Не удаляй пользовательские файлы и не переписывай несвязанные изменения.
- После завершения этапа проверь статус и diff, выполни применимые проверки, обнови `ROADMAP.md` и `TASKS.md`, затем commit и push без force.
