# Архитектура

## Статус

Локальный каркас Этапа 1 создан: React/Vite SPA и Hono Worker используют один Cloudflare Workers Vite build; D1 migration проверяется локально. Внешние Cloudflare ресурсы и Telegram flow не созданы и не проверены. Решения пересматриваются при появлении безопасных доступов и подтверждённых требований.

## Контекст и ограничения

Продукт — Telegram-бот и Mini App для управления AI-агентом, который отвечает от имени пользователя только через разрешённое Telegram Business-подключение. Обычный Bot API не предоставляет произвольный доступ ко всем личным перепискам. Система показывает только данные, фактически полученные после подключения и в пределах выданных пользователем прав. Полная история старых чатов не обещается.

Локальные исходники, npm manifest/lock, миграция, Wrangler конфигурация и CI теперь есть. Аккаунт Cloudflare, действующие credentials, Telegram bot/channel и домен требуют проверки владельцем. Ранее присланные в чат Cloudflare API и R2 credentials считать раскрытыми: не применять и отозвать/ротировать до использования.

## Целевая схема

```text
Telegram Mini App (React + Vite + TypeScript)
                 |
                 | HTTPS, Telegram initData
                 v
Один Cloudflare Worker (статические assets + Hono API + Telegram webhook)
          |                  |                 |
          v                  v                 v
         D1             Telegram Bot API    AI providers
     пользовательские   webhook и Business   серверные adapters
     данные и события   только выданные права
```

Один Worker обслуживает Mini App, API и webhook. Это снижает число независимых точек деплоя. Cloudflare Workers поддерживает static assets, а Cloudflare Vite plugin предназначен для интеграции Vite с runtime Workers; конкретную конфигурацию надо подтвердить при создании приложения.

## Компоненты

- **Mini App:** React, Vite, TypeScript; официальный Telegram Mini Apps SDK; mobile-first интерфейс.
- **Worker/API:** TypeScript и Hono; сейчас есть только `GET /api/health`, который проверяет D1 через `SELECT 1`. Авторизация Telegram `initData`, пользовательские endpoints и проверка владельца ресурсов не реализованы.
- **Telegram webhook:** обычные bot updates и поддерживаемые Business updates; проверка webhook secret, идемпотентность, права и отзыв подключения.
- **D1:** пользователи, Business connections, доступные диалоги/сообщения, настройки агента, документы, модели/providers, usage, ledger и аудит через миграции.
- **AI adapters:** серверные интеграции; ключи только в Cloudflare secrets; данные usage сохраняются, когда провайдер их предоставляет.
- **R2/KV:** не входят в начальный MVP без подтверждённой необходимости. R2 можно рассмотреть для загруженных документов; KV — для подходящих краткоживущих данных, не как основную БД.

## Потоки данных

1. Bot webhook проверяет подписку через `getChatMember`, если обязательный канал настроен.
2. Mini App отправляет `initData`; Worker проверяет подпись и свежесть `auth_date`, затем определяет пользователя.
3. Business webhook проверяет источник, connection, права, владельца диалога и идемпотентность до обработки.
4. AI pipeline использует настройки пользователя и разрешённый provider; отправляет ответ только при допустимом доступе и сохраняет доступные фактические события.
5. Отзыв Business connection прекращает автоматическую обработку, согласно поддерживаемому API.

Детальные требования авторизации и приватности приведены в `SECURITY.md`; проектируемые группы API — в `API.md`.

## Деплой

Один deployable Worker со статическими assets, API и webhook опубликован на `https://ecstasy.orskiyghost.workers.dev`. GitHub Actions выполняет CI и deploy; remote D1 и webhook созданы. Preview/production разделение ещё не реализовано. Секреты не хранятся в Git.
