# Дизайн Этапа 0: аудит и проектирование

## Цель

Подготовить проверяемую основу Telegram AI Agent SaaS / Mini App, не начиная реализацию продукта и инфраструктуры.

## Текущее состояние

В репозитории только `README.md` и `telegram_ai_mini_app_prompt.md.txt`. Ветка `main` чистая и совпадает с `origin/main`. Файлы приложения, конфигурация, CI, домен и эквивалентная проектная документация отсутствуют. Поиск распространённых форматов секретов в отслеживаемых файлах совпадений не дал.

Подтверждены Git remote и ветка. Доступы к Cloudflare и Telegram, домен, имена бота и канала не предоставлены. Их значения не предполагаются.

## Подходы

1. **Cloudflare Pages для UI и отдельный Worker для API.** Разделяет деплой на две системы и добавляет координацию без существующей frontend-основы.
2. **Только статический сайт.** Не покрывает будущие API и Telegram webhook.
3. **Один Cloudflare Worker со статическими файлами и API — выбранный подход.** Сохраняет один механизм деплоя, поддерживает Mini App, API и webhook. Cloudflare D1 служит основной базой данных.

## Архитектурная основа

- TypeScript, React и Vite для будущего frontend.
- Cloudflare Workers для статики, API и Telegram webhook.
- Hono для API-маршрутизации; D1 для реляционных данных и миграций.
- Официальный Telegram Mini Apps SDK и Telegram Bot API.
- Telegram Business доступ ограничен подключением, выданными разрешениями и данными, доступными после подключения. Проект не обещает доступ к полной старой истории.
- R2 и KV не вводятся до подтверждённой необходимости.
- CI/CD, production/preview, домены и bindings требуют уточнения при наличии доступа и реализации.

## Цели и границы

В Этап 0 входят аудит, согласованная архитектура, документация из мастер-промпта, `.gitignore` и безопасный `.env.example`.

Не входят продуктовый код, установка зависимостей, миграции, конфигурация Cloudflare, секреты, GitHub Actions, webhook, деплой и реальные значения неизвестных настроек. Проверка сборки неприменима: исходного приложения и manifest-файлов нет.

## Документы и конфигурация

Создать `AGENTS.md`, `ARCHITECTURE.md`, `DESIGN_SYSTEM.md`, `ROADMAP.md`, `TASKS.md`, `ENVIRONMENT.md`, `DEPLOYMENT.md`, `SECURITY.md`, `API.md`, `CHANGELOG.md`, `.gitignore` и `.env.example`.

Документы должны различать подтверждённые факты, проектные решения и открытые вопросы. `.env.example` содержит только имена выбранных для будущего MVP переменных с пустыми значениями; он не объявляет конфигурацию реализованной. Все секреты остаются вне Git.

## Условия приёмки

- Все перечисленные файлы существуют и согласованы между собой.
- Документы фиксируют архитектуру, ограничения доступа Telegram Business, неизвестные внешние настройки и следующие этапы.
- `.gitignore` исключает локальные секреты и артефакты, но разрешает `.env.example`.
- В репозиторий не добавлены секреты, продуктовый код или настройки внешней инфраструктуры.
- После проверки изменения коммитятся и отправляются в `origin/main`.
